* Project Isidore

The third iteration of my personal website. It was quite fun building this with
Common Lisp circa 2020. LLM agents have since taken over post 2025. Pull
requests and patches -- see "project-isidore.asd" for the correct mailing
address -- are most welcome.

** Development Quick Start

Prerequisite(s): [[https://guix.gnu.org/][GNU Guix]], which provides [[http://www.sbcl.org/][SBCL]] and every Common Lisp dependency.
=guix.scm= defines the package, including the dependencies Guix lacks, and
its inputs are the development environment. CI builds with the Guix release
that =GUIX_VERSION= in =.github/workflows/deploy.yml= names.

The code is three parts served by one process, each a group of
package-inferred systems under =src/=:

- =site/= -- the personal website's pages, and the layout every page shares.
- =bible/= -- the Douay-Rheims reader: its graph-db store (=database=), the
  text and its search (=text=), and its pages (=reader=).
- =slack-bot/= -- the van-booking bot: its graph-db store (=database=), the
  language layers (=nlp=, =booking-nlp=), the schedule
  spreadsheet (=van-booking=, with the Apps Script it talks to in
  =van-booking.gs=), and the Slack endpoints and reminders (=bot=).

=main.lisp= starts them all (=initialize-application=); =store.lisp= is the
graph-db plumbing the two databases share. The tests mirror this tree under
=src/tests/= and use [[https://github.com/fukamachi/rove][Rove]].

1. Clone the repository and enter the development environment,

   #+begin_src bash
   $ git clone https://github.com/bhwdev/project-isidore.git && cd project-isidore
   $ guix shell -D -f guix.scm
   #+end_src

   =guix shell= caches the environment and rebuilds it when =guix.scm=
   changes.

2. Within [[https://www.gnu.org/software/emacs/][Emacs]] started from that shell, start a Common Lisp IDE ([[https://github.com/joaotavora/sly][SLY]]) REPL
   buffer with =M-x sly=. ASDF finds the dependencies through =XDG_CONFIG_DIRS=,
   which the shell sets.

   Claude Code works through [[https://github.com/cl-ai-project/cl-mcp][cl-mcp]], a REPL-backed MCP server, where that
   costs fewer tokens than reading files; =CLAUDE.md= says when and how it is
   set up.

3. Load Project Isidore, run its tests & start a local development server.
   Loading opens nothing; =initialize-application= opens the databases. The
   bible pages and search need the bible store and Montezuma index under
   =/var/local/project-isidore/=, which are not in the repository, so the
   bible tests skip without them.

   #+begin_src lisp
     CL-USER> (asdf:test-system "project-isidore")
     ;; Starts web server at http://localhost:8080.
     CL-USER> (project-isidore/main:initialize-application)
     CL-USER> (project-isidore/main:terminate-application)
   #+end_src

4. To build the executable, which compiles the system, runs the tests and
   then saves the program from a fresh image that loaded only the system,

   #+begin_src bash
     $ guix build -f guix.scm
     $ /gnu/store/...-project-isidore-1.2.2/bin/project-isidore
   #+end_src

5. To build the container image that production runs,

   #+begin_src bash
     $ guix pack -f docker \
         --image-tag=project-isidore --entry-point=bin/project-isidore \
         --symlink=/etc/ssl=etc/ssl --symlink=/usr/share/zoneinfo=share/zoneinfo \
         --file=guix.scm nss-certs tzdata
     $ podman load --input /gnu/store/...-docker-pack.tar.gz
   #+end_src

   Prefix =guix time-machine --commit=vGUIX_VERSION --= to =guix pack= to
   build it with CI's Guix, as production's image is.

   Production runs it as below: host networking (Hunchentoot on 127.0.0.1:8080,
   Slynk on 4005), catatonit as PID 1, the bible
   store and the data directory (the bot's store and graph-db's system
   directory) mounted from the host, secrets from an environment file. The image has no =/etc/passwd=, so =HOME= is set for UIOP.

   #+begin_src bash
     $ podman run --rm --init --network=host \
         --volume=/var/local/project-isidore:/var/local/project-isidore \
         --volume=/root/.local/share/project-isidore:/var/lib/project-isidore \
         --env=HOME=/root --env=PROJECT_ISIDORE_DATA=/var/lib/project-isidore/ \
         --env=SSL_CERT_DIR=/etc/ssl/certs \
         --env=SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt \
         --env=TZDIR=/usr/share/zoneinfo --env=TZ=America/Toronto \
         --env-file=secrets.env localhost/project-isidore:latest
   #+end_src

** Deployment

A push to =master= deploys. [[file:.github/workflows/deploy.yml][.github/workflows/deploy.yml]] builds the image with =guix
pack= on a GitHub-hosted arm64 runner (production is aarch64), pushes it to
=ghcr.io/bhwdev/project-isidore=, and connects to the production host with a key
that can do nothing there but run its deploy hook: pull that image by digest,
tag it =localhost/project-isidore:latest= and restart the service that runs it.
The host runs Guix System, and the hook, that service (root Podman, the host's
network, the data directories as volumes, the secrets as an env file) and
Caddy are its system configuration, kept outside this repository.
The workflow runs =ssh root@HOST IMAGE@DIGEST=; sshd hands =IMAGE@DIGEST= to the
hook in =SSH_ORIGINAL_COMMAND=, and the hook refuses (exit 64) anything but
=ghcr.io/bhwdev/project-isidore@sha256:= and 64 hex digits. One-time setup:

1. On the host, allow a new deploy key in root's authorized keys, for the hook
   only:

   #+begin_src text
     restrict,command="/gnu/store/...-project-isidore-deploy" ssh-ed25519 AAAA... project-isidore-deploy
   #+end_src

2. In the repository's settings on GitHub, create the environment =production=,
   limited to the =master= branch, with the secret =DEPLOY_SSH_KEY= (the private
   key) and the variables =DEPLOY_HOST= (the host's address) and =DEPLOY_KNOWN_HOSTS=
   (=ssh-keyscan= output for it).

3. Push. Once the image is on ghcr.io, make the =project-isidore= package public
   (its settings page on GitHub), or the host cannot pull it anonymously. The
   workflow can only write to a package it created; one that already exists (as
   =ghcr.io/bhwdev/project-isidore= does, from an earlier repository) refuses
   the push with =permission_denied: write_package= until the package's settings
   grant this repository the Write role under "Manage Actions access".

The Slack bot reads and writes the van schedule through a Google Apps Script
web app, =src/slack-bot/van-booking.gs=, which is deployed by hand: its header
says how. Deploy a change to it before the Lisp that relies on it.
